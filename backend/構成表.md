# バックエンド構成表

## バージョン情報

バージョンは [README.md の技術スタック](../README.md#技術スタック) にまとめている（Java・Spring Boot・Gradle・PostgreSQL と、主要な部品）。2か所に書くと食い違うもとになるので、ここには書かない。

## プロジェクト構成

| ファイル・フォルダ | 役割 |
| --- | --- |
| `build.gradle` | ビルド定義。使用するSpring Bootのバージョン・依存ライブラリ（Web, Data JPA, PostgreSQLドライバ等）と、静的解析（PMD・Checkstyle）の設定を記述。テスト用の部品（Testcontainers）もここに書く |
| `settings.gradle` | プロジェクト名（`backend`）の定義 |
| `gradlew` / `gradlew.bat` | Gradle本体を別途インストールしなくてもビルド・起動できるようにするラッパースクリプト（Mac/Linux用・Windows用） |
| `gradle/wrapper/` | ラッパーが使うGradle本体（`gradle-wrapper.jar`）とバージョン指定（`gradle-wrapper.properties`） |
| `.gitignore` / `.gitattributes` | Gitで無視するファイル（ビルド成果物等）・改行コード等の設定 |
| `src/main/java/.../BackendApplication.java` | アプリの起動エントリポイント（`main`メソッド） |
| `src/main/java/.../task/Task.java` | タスク1件を表すエンティティ（DBの`tasks`テーブルに対応）。status・priority は enum で持つ |
| `src/main/java/.../task/TaskStatus.java` | タスクの状態の enum（TODO・DOING・DONE）。JSON では `@JsonValue`・`@JsonCreator` で小文字（todo・doing・done）にする。決まった値以外は JSON を読む時点で断る（400） |
| `src/main/java/.../task/TaskPriority.java` | 優先度の enum（HIGH・MEDIUM・LOW）。JSON では小文字（high・medium・low）。作りは TaskStatus と同じ |
| `src/main/java/.../task/TaskStatusConverter.java` / `TaskPriorityConverter.java` | enum と DB の文字の変換係（JPA の AttributeConverter）。DB には小文字で保存する（JPA 標準の `@Enumerated` だと大文字で保存され、今のデータと合わないため） |
| `src/main/java/.../task/TaskResponse.java` | API の返事専用の型（DTO）。エンティティ Task をそのまま返さず、`TaskResponse.from(task)` で画面に見せる項目だけに詰め替えて返す |
| `src/main/java/.../task/TaskNotFoundException.java` | 「その id のタスクが見つからない」ことを表す例外。Controller が投げ、GlobalExceptionHandler が 404 の返事にする |
| `src/main/java/.../error/GlobalExceptionHandler.java` | グローバル例外ハンドラー（`@RestControllerAdvice`）。アプリのどこで起きたエラーも1か所で受け止め、ProblemDetail の形で返す（下の「エラーの返事」を参照） |
| `src/main/java/.../task/TaskRepository.java` | DBへのCRUD操作を行うインターフェース（Spring Data JPA）。`JpaSpecificationExecutor` も受け継ぎ、条件の部品（Specification）を渡して `findAll(条件, 並び順)` で取ってこられる |
| `src/main/java/.../task/TaskSpecifications.java` | 一覧の絞り込みの「条件の部品」（Specification）を作る。`textContains`（キーワード。LIKE の `%`・`_` はただの文字として探す）、`priorityIn`（優先度のどれか）、`dueMatches`（期限切れ／7日以内／期限なし）。条件が選ばれていないときは `Specification.unrestricted()`（条件なし）を返す |
| `src/main/java/.../task/DueFilter.java` | 期限の絞り込みの種類の enum（OVERDUE・WEEK・NONE）。URL では小文字（overdue・week・none）。作りは TaskPriority と同じ |
| `src/main/java/.../task/QueryParamConverters.java` | URL の `?priority=high`・`?due=overdue` の小文字を、TaskPriority・DueFilter に変える方法を Spring に登録する（`WebMvcConfigurer` の `addFormatters`）。決まった値以外なら 400 になる |
| `src/main/java/.../task/TaskController.java` | REST APIのエンドポイント定義（`/api/tasks`配下）。リクエストを受け取り、`@Valid` で入力をチェックし、レスポンスを返す。返事は TaskResponse（DTO）に変換してから返す。タスクが見つからないときは TaskNotFoundException を投げる（エラーの返事は自分で作らない）。DBの操作はすべて TaskService に任せる（Repository は直接使わない） |
| `src/main/java/.../task/TaskService.java` | 業務処理を行うService層（キーワード・優先度・期限の条件の部品を `Specification.allOf` でまとめ（AND）、列→並び順の順で取ってくる、タスク作成時に既定値と並び順を決める、列が変わったタスクを移動先の一番下に置くなど。一番下の並び順は、削除で番号に隙間があっても重ならないよう「列の最大値＋1」で決める）。読み取り・作成・更新（PUT／PATCH）・削除・並び替えを担当。`@Transactional` で、メソッドごとのDB操作を「全部成功か、全部取り消し」にする（読み取りは `readOnly`） |
| `src/main/java/.../task/TaskRequest.java` | タスク作成・更新時のリクエストボディの型（text は空欄不可・255文字まで、status／priority は enum なので決められた値のみ） |
| `src/main/java/.../task/TaskPatchRequest.java` | 一部だけ更新（PATCH）するときのリクエストボディの型（すべて省略可。送るなら text は空白だけ不可・255文字まで、status／priority は enum なので決められた値のみ） |
| `src/main/java/.../task/ReorderRequest.java` | 並び替えAPIのリクエストボディの型（status と orderedIds は必須、status は enum なので決められた値のみ） |
| `src/main/java/.../task/MoveRequest.java` | カード1枚を動かすAPI（move）のリクエストボディの型（status は必須。prevId＝すぐ上に入れるカードの ID。省略すると列の一番上） |
| `src/main/resources/application.properties` | 設定ファイル（ポート番号、DB接続情報など） |
| `src/main/resources/db/migration/V1__create_tasks_table.sql` | Flyway の SQL ファイル。tasks テーブルとインデックスを作る。起動時に Flyway が、まだ当てていない V番号のファイルを順番に当てる（テーブルを変えるときは新しい V番号のファイルを足す。[DB設計書.md](DB設計書.md) を参照） |
| `src/main/resources/db/migration/V2__sort_order_to_double.sql` | Flyway の SQL ファイル。sort_order を整数から小数（DOUBLE PRECISION）に変える（絞り込み中の並び替えのため） |
| `config/checkstyle/checkstyle.xml` | Checkstyle の決まり（どの書き方をチェックするか）。Gradle が最初に探す場所なので、`build.gradle` で場所を指定しなくても使われる |
| `src/test/java/.../TestcontainersConfiguration.java` | テスト用の設定。テストのたびに Docker で使い捨ての PostgreSQL 17 を起動し、`@ServiceConnection` で Spring Boot の接続先をそこに向ける（開発用の DB は使わない） |
| `src/test/java/.../BackendApplicationTests.java` | アプリが起動できるかのテスト（DB は TestcontainersConfiguration の使い捨ての PostgreSQL） |
| `src/test/java/.../task/TaskApiTest.java` | タスクの API のテスト（14件）。アプリを丸ごと起動し、MockMvcTester で API を呼んで返事と DB の中身を確かめる（下の「自動テスト」を参照） |

## 実行時の設定値（`application.properties`）

| 項目 | 値 |
| --- | --- |
| アプリ名 | backend |
| ポート番号 | 8080 |
| DB接続先 | `jdbc:postgresql://localhost:5432/taskdb`（Docker の PostgreSQL。Windows に直接インストールした PostgreSQL のサービスは停止しておく） |
| DBユーザー | 環境変数 `DB_USERNAME`。なければ postgres（開発用） |

| ddl-auto | validate（テーブルを作る・変えるのは Flyway。Hibernate は Task.java とテーブルが合っているかを確かめるだけで、合わなければ起動を止める） |
| flyway.baseline-on-migrate | true（Flyway の記録がないデータ入りの DB は「V1 まで済み」とみなし、V1 を流さない。空の DB では V1 から流れる） |
| open-in-view | false（DBの操作は Service の `@Transactional` の中だけで行う） |

## 静的解析（PMD）

PMD は、Java のコードから「バグになりやすい書き方」を見つける道具。規則は PMD が用意している `quickstart` を使う（`build.gradle` の `pmd { }`）。

| 実行場所 | コマンド | 説明 |
| --- | --- | --- |
| `backend`フォルダ | `./gradlew pmdMain pmdTest` | 本体とテストのコードをチェックする。1件でも見つかると失敗し、場所と規則名が表示される（`./gradlew check` にも含まれる） |

- 見つかったものは、基本は直す。PMD の指摘が Spring の書き方と合わない（的外れな）ときだけ、その場所に `@SuppressWarnings("PMD.規則名")` を付けて止め、止めた理由をコメントに書く（例：[BackendApplication.java](src/main/java/com/taskmanagement/backend/BackendApplication.java) の `UseUtilityClass`）
- 止める範囲はなるべく狭くする（プロジェクト全体で止めると、ほかの場所の本当の問題も見逃すため）
- GitHub Actions（`taskmanagement/.github/workflows/ci.yml`）でも、PR ごとに `./gradlew check` が自動で動く

## 書き方のチェック（Checkstyle）

Checkstyle は、コードの「書き方がそろっているか」を見る道具（PMD は「バグになりやすい書き方」を見る）。決まりは `config/checkstyle/checkstyle.xml` に書いてあり、今のコードに合う基本的なものだけを選んでいる。

| 実行場所 | コマンド | 説明 |
| --- | --- | --- |
| `backend`フォルダ | `./gradlew checkstyleMain checkstyleTest` | 本体とテストのコードをチェックする。1件でも見つかると失敗し、ファイル名・行番号・規則名が表示される（`./gradlew check` にも含まれる） |

| 決まり | 内容 |
| --- | --- |
| FileTabCharacter | インデントにタブ文字を使わない（スペース4つ） |
| NewlineAtEndOfFile | ファイルの最後は改行で終える |
| LineLength | 1行は120文字まで |
| AvoidStarImport・UnusedImports・RedundantImport | `import ...*;` を使わない。使っていない・重なっている import を残さない |
| 名前の付け方（TypeName・MethodName・ConstantName など） | クラスは `TaskService`、変数やメソッドは `taskService`、定数は `LOG` の形 |
| NeedBraces | `if`・`for` などは、1行でも `{ }` で囲む |
| そのほか | 1行に1つの文だけ（OneStatementPerLine）、空の catch を書かない（EmptyCatchBlock）、記号の前後に空白（WhitespaceAround）など |

## 自動テスト

テストは JUnit Jupiter で書き、DB は Testcontainers が Docker で用意する使い捨ての PostgreSQL を使う。開発用の DB（docker compose の 5432）は使わないので、起動していなくてもテストが動き、開発用のデータも汚さない（Docker Desktop は起動しておく）。

| 実行場所 | コマンド | 説明 |
| --- | --- | --- |
| `backend`フォルダ | `./gradlew test` | テストだけを動かす。結果は `build/reports/tests/test/index.html` で見られる |
| `backend`フォルダ | `./gradlew check` | コンパイル・PMD・Checkstyle・テストをまとめて動かす（GitHub Actions と同じ） |

`TaskApiTest` で確かめていること：

| 場面 | 確かめること |
| --- | --- |
| 登録 | status・priority を省略すると todo・medium になり、JSON は小文字で返る |
| 削除のあとの登録 | 削除で並び順に隙間ができても、新しいタスクは「列の最大値＋1」に入る（以前あった、番号が重なる不具合の再発防止） |
| 並び替え | 送った ID の順に 0・1・2 番が振り直され、列も移る（DB の中身まで確かめる） |
| 削除 | 204 が返り、そのあと取得すると 404 になる |
| 絞り込み（優先度） | priority を2つ書くと、そのどちらかの優先度のタスクだけが返る |
| 絞り込み（期限） | overdue・week・none が、それぞれ正しいタスクだけを返す。境目（今日は期限切れに入らない、今日＋6日は7日以内に入り、＋7日は入らない）も確かめる。期限日は `LocalDate.now()` から作るので、いつ動かしても同じ結果になる |
| 絞り込み（組み合わせ） | keyword と priority を一緒に書くと、両方を満たすタスクだけが返る（片方だけ合うタスクも用意して、OR になっていないことを確かめる） |
| キーワードの `%` | `100%` で検索しても、`%` を「何でもよい文字」として扱わない |
| 入力ミス | タスク名が空・256 文字、status が決まっていない値、並び替えで status がない → 400 と理由（`errors`）。DB には何も保存されない。絞り込みの priority・due が決まっていない値 → 400 |
| 見つからない | 存在しない id を書き換える → 404 と理由（`detail`） |

- テストごとに（`@BeforeEach`）タスクを全部消してから始める。前のテストのデータが混ざると、結果がテストの順番で変わってしまうため

## 起動手順（DB + バックエンド）

PostgreSQLはインストール不要で、Dockerコンテナとして起動する（設定ファイルは`taskmanagement/docker-compose.yml`）。

| 順番 | 実行場所 | コマンド | 説明 |
| --- | --- | --- | --- |
| 1 | `taskmanagement`フォルダ | `docker compose up -d` | PostgreSQLをDockerで起動 |
| 2 | `backend`フォルダ | `./gradlew bootRun` | バックエンド（Java）を起動（初回起動時に`tasks`テーブルが自動作成される） |
| 3（任意） | `taskmanagement`フォルダ | `docker compose exec -T postgres psql -U postgres -d taskdb < db/seed-test-data.sql` | テストデータ10件を投入（既存データはすべて消えて入れ直される） |

DBを止めるときは`taskmanagement`フォルダで`docker compose down`を実行する（`docker compose down -v`にするとデータも消えるので注意）。

## 提供しているREST APIエンドポイント

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | /api/tasks | 全タスク取得 |
| GET | /api/tasks?keyword={キーワード}&priority={優先度}&due={期限} | 条件で絞り込んでタスクを取得（どれも省略可。書いた条件を全部満たすものだけ）。keyword：タスク名の部分一致（大文字小文字を区別しない）。priority：high／medium／low（何度でも書ける）。due：overdue（今日より前）／week（今日〜今日＋6日）／none（期限なし）。priority・due が決まった値以外なら400 |
| GET | /api/tasks/{id} | タスクを1件取得（存在しない場合は404） |
| POST | /api/tasks | タスク作成（列の一番下に追加。status 省略時は todo、priority 省略時は medium。成功時は201、入力が不正なら400） |
| PUT | /api/tasks/{id} | タスクを丸ごと更新（status／priority 省略時は今の値のまま。列が変わるときは移動先の一番下に置く。存在しない場合は404、入力が不正なら400） |
| PATCH | /api/tasks/{id} | タスクの一部だけを更新（送った項目だけを書き換える。存在しない場合は404、入力が不正なら400） |
| DELETE | /api/tasks/{id} | タスク削除（成功時は204、存在しない場合は404） |
| PUT | /api/tasks/{id}/move | ドラッグ用。タスク1件を、指定した列の prevId のタスクのすぐ下（prevId を省くと一番上）に移す。番号は、上のタスクと DB で本当にすぐ下のタスクの真ん中。成功時は200（動かしたあとのタスク）、タスクがなければ404、prevId が別の列なら400 |
| PUT | /api/tasks/reorder | 自動並び替え用。指定した列の中で、送った ID のタスクどうしの番号（席）を入れ替え、送った順に並べる。送らなかったタスクの番号は変えない。成功時は204、入力が不正・別の列のタスクが混じっていれば400 |

## エラーの返事（ProblemDetail）

エラーの返事は、どの API でも ProblemDetail（RFC 9457。Spring 標準のエラーの形）にそろえている。Content-Type は `application/problem+json`。作っているのは [GlobalExceptionHandler.java](src/main/java/com/taskmanagement/backend/error/GlobalExceptionHandler.java) の1か所だけ。

```json
{"type":"about:blank","title":"Bad Request","status":400,
 "detail":"入力内容に誤りがあります","instance":"/api/tasks",
 "errors":{"text":"タスク名を入力してください"}}
```

| 場面 | status | detail | その他 |
| --- | --- | --- | --- |
| 入力チェック違反（`@Valid`。text が空・256文字以上、並び替えの status なし など） | 400 | 入力内容に誤りがあります | `errors` に「項目名 → 理由」（例：`orderedIds[1]` は orderedIds の2番目） |
| JSON が読めない（形が崩れている、status・priority に決まっていない値） | 400 | 正しい値を案内する文 | — |
| タスクが見つからない（TaskNotFoundException） | 404 | id が ○ のタスクは見つかりません | — |
| id が数字でない・存在しない URL など（Spring の決まった例外） | 400・404 など | Spring が作る英語の文 | 親クラス（ResponseEntityExceptionHandler）が作る |
| 上のどれでもない思いがけないエラー | 500 | サーバーでエラーが起きました | 例外の中身は返さず、サーバーのログにだけ出す |
