| `src/main/java/.../BackendApplication.java` | アプリの起動エントリポイント（`main`メソッド） |
| `src/main/java/.../column/BoardColumn.java` | 列1つを表すエンティティ（DBの`board_columns`テーブルに対応）。名前・並び順・基本の列の印（fixed）・完了の列の印（done）。2つの印は作ったあとで変えない |
| `src/main/java/.../column/BoardColumnRepository.java` | 列のDB操作。左から順の一覧、右端・左端の列、完了の列（`findByDoneTrue`）を取る |
| `src/main/java/.../column/BoardColumnService.java` | 列の業務処理（作る＝右端に足す、名前を変える、並べ替え、消す）。基本の列（やるべきこと・進行中・終わったこと）・タスクが入っている列は消せない（409。確かめてから消すまでの間にほかの端末がタスクを足し、DB の外部キーに止められたときも 409 にする）。完了の列は「終わったこと」に決まっていて、付け替えはしない |
| `src/main/java/.../column/BoardColumnController.java` | 列の REST API（`/api/columns`配下）。DBの操作は BoardColumnService に任せる |
| `src/main/java/.../column/BoardColumnRequest.java` / `BoardColumnOrderRequest.java` / `BoardColumnResponse.java` | 列の API の入れ物（作る・名前を変えるときの name、並べ替えるときの orderedIds、返事の DTO） |
| `src/main/java/.../column/ColumnNotFoundException.java` | 「その id の列が見つからない」ことを表す例外（TaskNotFoundException と同じ形）。BoardColumnService が投げ、GlobalExceptionHandler が 404 の返事にする |
| `src/main/java/.../task/Task.java` | タスク1件を表すエンティティ（DBの`tasks`テーブルに対応）。どの列にいるかは列の番号（columnId）で持ち、priority は enum で持つ |
| `src/main/java/.../task/TaskPriority.java` | 優先度の enum（HIGH・MEDIUM・LOW）。JSON では `@JsonValue`・`@JsonCreator` で小文字（high・medium・low）にする。決まった値以外は JSON を読む時点で断る（400） |
| `src/main/java/.../task/TaskPriorityConverter.java` | enum と DB の文字の変換係（JPA の AttributeConverter）。DB には小文字で保存する（JPA 標準の `@Enumerated` だと大文字で保存され、今のデータと合わないため） |
| `src/main/java/.../task/TaskResponse.java` | API の返事専用の型（DTO）。エンティティ Task をそのまま返さず、`TaskResponse.from(task)` で画面に見せる項目だけに詰め替えて返す |
| `src/main/java/.../task/TaskNotFoundException.java` | 「その id のタスクが見つからない」ことを表す例外。Controller が投げ、GlobalExceptionHandler が 404 の返事にする |
| `src/main/java/.../error/GlobalExceptionHandler.java` | グローバル例外ハンドラー（`@RestControllerAdvice`）。アプリのどこで起きたエラーも1か所で受け止め、ProblemDetail の形で返す（下の「エラーの返事」を参照） |
| `src/main/java/.../task/TaskRepository.java` | DBへのCRUD操作を行うインターフェース（Spring Data JPA）。`JpaSpecificationExecutor` も受け継ぎ、条件の部品（Specification）を渡して `findAll(条件, 並び順)` で取ってこられる |
| `src/main/java/.../task/TaskSpecifications.java` | 一覧の絞り込みの「条件の部品」（Specification）を作る。`textContains`（キーワード。LIKE の `%`・`_` はただの文字として探す）、`priorityIn`（優先度のどれか）、`dueMatches`（期限切れ／7日以内／期限なし）。条件が選ばれていないときは `Specification.unrestricted()`（条件なし）を返す |
| `src/main/java/.../task/DueFilter.java` | 期限の絞り込みの種類の enum（OVERDUE・WEEK・NONE）。URL では小文字（overdue・week・none）。作りは TaskPriority と同じ |
| `src/main/java/.../task/QueryParamConverters.java` | URL の `?priority=high`・`?due=overdue` の小文字を、TaskPriority・DueFilter に変える方法を Spring に登録する（`WebMvcConfigurer` の `addFormatters`）。決まった値以外なら 400 になる |
| `src/main/java/.../task/TaskController.java` | REST APIのエンドポイント定義（`/api/tasks`配下）。リクエストを受け取り、`@Valid` で入力をチェックし、レスポンスを返す。返事は TaskResponse（DTO）に変換してから返す。タスクが見つからないときは TaskNotFoundException を投げる（エラーの返事は自分で作らない）。DBの操作はすべて TaskService に任せる（Repository は直接使わない） |
| `src/main/java/.../task/TaskService.java` | 業務処理を行うService層（キーワード・優先度・期限の条件の部品を `Specification.allOf` でまとめ（AND）、列→並び順の順で取ってくる、タスク作成時に既定値（一番左の列・medium）と並び順を決める、列が変わったタスクを移動先の一番下に置くなど。一番下の並び順は、削除で番号に隙間があっても重ならないよう「列の最大値＋1」で決める。送られてきた列の番号が本当にあるかを確かめる（`requireColumn`、なければ400））。読み取り・作成・更新（PUT／PATCH）・削除・並び替え・書き出し・読み込みを担当。`@Transactional` で、メソッドごとのDB操作を「全部成功か、全部取り消し」にする（読み取りは `readOnly`） |
| `src/main/java/.../task/TaskRequest.java` | タスク作成・更新時のリクエストボディの型（text は空欄不可・255文字まで、columnId は列の番号（省略可）、priority は enum なので決められた値のみ） |
| `src/main/java/.../task/TaskPatchRequest.java` | 一部だけ更新（PATCH）するときのリクエストボディの型（すべて省略可。送るなら text は空白だけ不可・255文字まで、columnId は列の番号、priority は enum なので決められた値のみ） |
| `src/main/java/.../task/ReorderRequest.java` | 並び替えAPIのリクエストボディの型（columnId と orderedIds は必須） |
| `src/main/java/.../task/MoveRequest.java` | カード1枚を動かすAPI（move）のリクエストボディの型（columnId は必須。prevId＝すぐ上に入れるカードの ID。省略すると列の一番上） |
| `src/main/java/.../task/TaskFile.java` | 書き出し・読み込みのファイル全体の型（version・exportedAt と、version 2 なら columns、version 1 なら tasks）。書き出すのは `CURRENT_VERSION`（2）。読み込めるのは 1 と 2 |
| `src/main/java/.../task/TaskFileColumn.java` | ファイル（version 2）に入れる列1つの型（name・fixed・done・tasks）。列の順・タスクの順は、ファイルに書いた順。fixed・done は省略すると false。読み込むときは、基本の列がちょうど3つ・完了の列がちょうど1つで基本の列のどれか、を TaskService が確かめる |
| `src/main/java/.../task/TaskFileItem.java` | ファイル（version 2）に入れるタスク1件の型（text・priority・dueDate。id・列・並び順はなし）。`from(Task)` で DB のタスクから作る |
| `src/main/java/.../task/TaskFileV1Item.java` | 古い版（version 1）のファイルのタスク1件の型（text・status・priority・dueDate・sortOrder）。読み込むときだけ使い、status（todo・doing・done）ごとに3つの列に入れる |
| `src/main/resources/application.properties` | 設定ファイル（ポート番号、DB接続情報など） |
| `src/main/resources/db/migration/V1__create_tasks_table.sql` | Flyway の SQL ファイル。tasks テーブルとインデックスを作る。起動時に Flyway が、まだ当てていない V番号のファイルを順番に当てる（テーブルを変えるときは新しい V番号のファイルを足す。[DB設計書.md](DB設計書.md) を参照） |
| `src/main/resources/db/migration/V2__sort_order_to_double.sql` | Flyway の SQL ファイル。sort_order を整数から小数（DOUBLE PRECISION）に変える（絞り込み中の並び替えのため） |
| `src/main/resources/db/migration/V3__create_board_columns.sql` | Flyway の SQL ファイル。board_columns テーブルを作って今までの3列を入れ、tasks の status を column_id（外部キー）に置き換える（列を自由に追加・削除するため） |

## 静的解析（PMD）

PMD は、Java のコードから「バグになりやすい書き方」を見つける道具。規則は PMD が用意している `quickstart` を使う（`build.gradle` の `pmd { }`）。

| 実行場所 | コマンド | 説明 |
| --- | --- | --- |
| `backend`フォルダ | `./gradlew pmdMain pmdTest` | 本体とテストのコードをチェックする。1件でも見つかると失敗し、場所と規則名が表示される（`./gradlew check` にも含まれる） |

- 見つかったものは、基本は直す。PMD の指摘が Spring の書き方と合わない（的外れな）ときだけ、その場所に `@SuppressWarnings("PMD.規則名")` を付けて止め、止めた理由をコメントに書く（例：[BackendApplication.java](src/main/java/com/taskmanagement/backend/BackendApplication.java) の `UseUtilityClass`）
- 止める範囲はなるべく狭くする（プロジェクト全体で止めると、ほかの場所の本当の問題も見逃すため）
- GitHub Actions（`taskmanagement/.github/workflows/ci.yml`）でも、PR ごとに `./gradlew check` が自動で動く

## 書き方のチェック（Checkstyle）

Checkstyle は、コードの「書き方がそろっているか」を見る道具（PMD は「バグになりやすい書き方」を見る）。決まりは `config/checkstyle/checkstyle.xml` に書いてあり、今のコードに合う基本的なものだけを選んでいる。

| 実行場所 | コマンド | 説明 |
| --- | --- | --- |
| `backend`フォルダ | `./gradlew checkstyleMain checkstyleTest` | 本体とテストのコードをチェックする。1件でも見つかると失敗し、ファイル名・行番号・規則名が表示される（`./gradlew check` にも含まれる） |

| 決まり | 内容 |
| --- | --- |
| FileTabCharacter | インデントにタブ文字を使わない（スペース4つ） |
| NewlineAtEndOfFile | ファイルの最後は改行で終える |
| LineLength | 1行は120文字まで |
| AvoidStarImport・UnusedImports・RedundantImport | `import ...*;` を使わない。使っていない・重なっている import を残さない |
| 名前の付け方（TypeName・MethodName・ConstantName など） | クラスは `TaskService`、変数やメソッドは `taskService`、定数は `LOG` の形 |
| NeedBraces | `if`・`for` などは、1行でも `{ }` で囲む |
| そのほか | 1行に1つの文だけ（OneStatementPerLine）、空の catch を書かない（EmptyCatchBlock）、記号の前後に空白（WhitespaceAround）など |

## 自動テスト

テストは JUnit Jupiter で書き、DB は Testcontainers が Docker で用意する使い捨ての PostgreSQL を使う。開発用の DB（docker compose の 5432）は使わないので、起動していなくてもテストが動き、開発用のデータも汚さない（Docker Desktop は起動しておく）。

| 実行場所 | コマンド | 説明 |
| --- | --- | --- |
| `backend`フォルダ | `./gradlew test` | テストだけを動かす。結果は `build/reports/tests/test/index.html` で見られる |
| `backend`フォルダ | `./gradlew check` | コンパイル・PMD・Checkstyle・テストをまとめて動かす（GitHub Actions と同じ） |

`TaskApiTest` で確かめていること：

| 場面 | 確かめること |
| --- | --- |
| 登録 | columnId・priority を省略すると一番左の列・medium になり、JSON は小文字で返る |
| 削除のあとの登録 | 削除で並び順に隙間ができても、新しいタスクは「列の最大値＋1」に入る（以前あった、番号が重なる不具合の再発防止） |
| 完了ボタン | PATCH で完了の列の番号を送ると、完了の列の一番下に移る |
| 並び替え（move・reorder） | move は上のカードと DB で本当にすぐ下のカードの真ん中に入る（すき間がなければ振り直す）。reorder は送ったカードどうしで席を入れ替え、送らなかったカードは動かさない。別の列のカードが混じると 400 |
| 削除 | 204 が返り、そのあと取得すると 404 になる |
| 絞り込み（優先度） | priority を2つ書くと、そのどちらかの優先度のタスクだけが返る |
| 絞り込み（期限） | overdue・week・none が、それぞれ正しいタスクだけを返す。境目（今日は期限切れに入らない、今日＋6日は7日以内に入り、＋7日は入らない）も確かめる。期限日は `LocalDate.now()` から作るので、いつ動かしても同じ結果になる |
| 絞り込み（組み合わせ） | keyword と priority を一緒に書くと、両方を満たすタスクだけが返る（片方だけ合うタスクも用意して、OR になっていないことを確かめる） |
| キーワードの `%` | `100%` で検索しても、`%` を「何でもよい文字」として扱わない |
| 入力ミス | タスク名が空・256 文字、並び替えで columnId がない → 400 と理由（`errors`）。ない列の番号 → 400 と理由（`detail`）。DB には何も保存されない。絞り込みの priority・due が決まっていない値 → 400 |
| 見つからない | 存在しない id を書き換える → 404 と理由（`detail`） |
| 書き出し・読み込み | 書き出しは version 2 の列ごとの形で、id なし。読み込むと列もタスクもファイルどおりに置き換わる。version 1 のファイルも3列に入れて読める。おかしいタスクがある・基本の列がちょうど3つでない・完了の列がちょうど1つでない・完了の列が基本の列でない・知らない version → 400 で何も変えない。書き出したファイルを読み込むと、足した列も含めて元に戻る |

`BoardColumnApiTest` で確かめていること：

| 場面 | 確かめること |
| --- | --- |
| 一覧・作る | 左から順に返る。作った列は名前の前後の空白が取れ、完了の印なしで右端に入る。名前が空なら 400 |
| 名前を変える | 名前が変わる。ない列なら 404 |
| 完了の列 | 付け替えの URL（`PUT /api/columns/{id}/done`）はなく、完了の列は「終わったこと」のまま |
| 並べ替え | 送った順に左から並ぶ。足りない・重なっている ID なら 400 で並びは変わらない |
| 消す | 足した空の列は 204。タスクが入っている列・基本の3列は 409 で残る。ない列は 404 |

- テストごとに（`@BeforeEach`）タスクと列を全部消し、「やるべきこと／進行中／終わったこと」の3列を作り直してから始める。前のテストのデータが混ざると、結果がテストの順番で変わってしまうため

## 起動手順（DB + バックエンド）

PostgreSQLはインストール不要で、Dockerコンテナとして起動する（設定ファイルは`taskmanagement/docker-compose.yml`）。

| 順番 | 実行場所 | コマンド | 説明 |
| --- | --- | --- | --- |
| 1 | `taskmanagement`フォルダ | `docker compose up -d` | PostgreSQLをDockerで起動 |
| 2 | `backend`フォルダ | `./gradlew bootRun` | バックエンド（Java）を起動（起動時に Flyway が`board_columns`・`tasks`テーブルを作る・直す） |
| 3（任意） | `taskmanagement`フォルダ | `docker compose exec -T postgres psql -U postgres -d taskdb < db/seed-test-data.sql` | テストデータ（3列とタスク10件）を投入（既存の列とタスクはすべて消えて入れ直される） |

DBを止めるときは`taskmanagement`フォルダで`docker compose down`を実行する（`docker compose down -v`にするとデータも消えるので注意）。

## 提供しているREST APIエンドポイント

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | /api/columns | 全部の列を左から順に取得（id・name・sortOrder・done） |
| POST | /api/columns | 列を作る（`{"name": "..."}`。右端に、基本の列・完了の列の印なしで入る（あとから消せる列）。成功時は201、名前が空・256文字以上なら400） |
| PUT | /api/columns/{id} | 列の名前を変える（`{"name": "..."}`。存在しない場合は404） |
| PUT | /api/columns/order | 列を並べ替える（`{"orderedIds": [...]}`。全部の列の ID を1回ずつ。そうでなければ400） |
| DELETE | /api/columns/{id} | 列を消す（成功時は204、存在しない場合は404、基本の列・タスクが入っている列は409） |
| GET | /api/tasks | 全タスク取得 |
| GET | /api/tasks?keyword={キーワード}&priority={優先度}&due={期限} | 条件で絞り込んでタスクを取得（どれも省略可。書いた条件を全部満たすものだけ）。keyword：タスク名の部分一致（大文字小文字を区別しない）。priority：high／medium／low（何度でも書ける）。due：overdue（今日より前）／week（今日〜今日＋6日）／none（期限なし）。priority・due が決まった値以外なら400 |
| GET | /api/tasks/{id} | タスクを1件取得（存在しない場合は404） |
| POST | /api/tasks | タスク作成（列の一番下に追加。columnId 省略時は一番左の列、priority 省略時は medium。成功時は201、入力が不正・ない列なら400） |
| PUT | /api/tasks/{id} | タスクを丸ごと更新（columnId／priority 省略時は今の値のまま。列が変わるときは移動先の一番下に置く。存在しない場合は404、入力が不正・ない列なら400） |
| PATCH | /api/tasks/{id} | タスクの一部だけを更新（送った項目だけを書き換える。存在しない場合は404、入力が不正なら400） |
| DELETE | /api/tasks/{id} | タスク削除（成功時は204、存在しない場合は404） |
| PUT | /api/tasks/{id}/move | ドラッグ用。タスク1件を、指定した列の prevId のタスクのすぐ下（prevId を省くと一番上）に移す。番号は、上のタスクと DB で本当にすぐ下のタスクの真ん中。成功時は200（動かしたあとのタスク）、タスクがなければ404、prevId が別の列なら400 |
| PUT | /api/tasks/reorder | 自動並び替え用。指定した列の中で、送った ID のタスクどうしの番号（席）を入れ替え、送った順に並べる。送らなかったタスクの番号は変えない。成功時は204、入力が不正・別の列のタスクが混じっていれば400 |
| GET | /api/tasks/export | 書き出し。全部の列とタスクを TaskFile（version 2）の JSON で返し、`Content-Disposition: attachment; filename="tasks-日付.json"` を付ける。成功時は200 |
| POST | /api/tasks/import | 読み込み。全部の列とタスクを消して、送られた TaskFile の列とタスクに置き換える（1つのトランザクション。並び順はファイルに書いた順に 0, 1, 2… と振り直す）。version 1 のファイルは3列（やるべきこと／進行中／終わったこと）に入れる。成功時は204、入力が不正・完了の列がちょうど1つでない・version が 1・2 でない・JSON が読めなければ400（何も変えない） |

## エラーの返事（ProblemDetail）

エラーの返事は、どの API でも ProblemDetail（RFC 9457。Spring 標準のエラーの形）にそろえている。Content-Type は `application/problem+json`。作っているのは [GlobalExceptionHandler.java](src/main/java/com/taskmanagement/backend/error/GlobalExceptionHandler.java) の1か所だけ。

```json
{"type":"about:blank","title":"Bad Request","status":400,
 "detail":"入力内容に誤りがあります","instance":"/api/tasks",
 "errors":{"text":"タスク名を入力してください"}}
```

| 場面 | status | detail | その他 |
| --- | --- | --- | --- |
| 入力チェック違反（`@Valid`。text が空・256文字以上、並び替えの columnId なし など） | 400 | 入力内容に誤りがあります | `errors` に「項目名 → 理由」（例：`orderedIds[1]` は orderedIds の2番目） |
| JSON が読めない（形が崩れている、priority に決まっていない値、columnId が数字でない） | 400 | JSON の形と、項目の値（列の番号は数字、優先度は high・medium・low）を確かめるよう案内する文（壊れたファイルの読み込みにも合う言い方） | — |
| ない列の番号・別の列のカード・おかしなファイルなど（Service の `ResponseStatusException`） | 400 | 理由の文（例：id が ○ の列はありません） | — |
| タスクが見つからない（TaskNotFoundException） | 404 | id が ○ のタスクは見つかりません | — |
| 列が見つからない（ColumnNotFoundException） | 404 | id が ○ の列は見つかりません | — |
| 基本の列・タスクが入っている列を消そうとした | 409 | 消せない理由と、どうすればよいかの文 | — |
| id が数字でない・存在しない URL など（Spring の決まった例外） | 400・404 など | Spring が作る英語の文 | 親クラス（ResponseEntityExceptionHandler）が作る |
| 上のどれでもない思いがけないエラー | 500 | サーバーでエラーが起きました | 例外の中身は返さず、サーバーのログにだけ出す |
