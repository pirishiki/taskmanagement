# バックエンド構成表

| --- | --- |

## プロジェクト構成

| ファイル・フォルダ | 役割 |
| --- | --- |
| `build.gradle` | ビルド定義。使用するSpring Bootのバージョン・依存ライブラリ（Web, Data JPA, PostgreSQLドライバ等）と、静的解析（PMD）の設定を記述 |
| `settings.gradle` | プロジェクト名（`backend`）の定義 |
| `gradlew` / `gradlew.bat` | Gradle本体を別途インストールしなくてもビルド・起動できるようにするラッパースクリプト（Mac/Linux用・Windows用） |
| `gradle/wrapper/` | ラッパーが使うGradle本体（`gradle-wrapper.jar`）とバージョン指定（`gradle-wrapper.properties`） |
| `.gitignore` / `.gitattributes` | Gitで無視するファイル（ビルド成果物等）・改行コード等の設定 |
| `src/main/java/.../BackendApplication.java` | アプリの起動エントリポイント（`main`メソッド） |
| `src/main/java/.../task/Task.java` | タスク1件を表すエンティティ（DBの`tasks`テーブルに対応） |
| `src/main/java/.../task/TaskRepository.java` | DBへのCRUD操作を行うインターフェース（Spring Data JPA） |
| `src/main/java/.../task/TaskController.java` | REST APIのエンドポイント定義（`/api/tasks`配下）。リクエストを受け取り、`@Valid` で入力をチェックし、レスポンス（200/404など）を返す。DBの操作はすべて TaskService に任せる（Repository は直接使わない） |
| `src/main/java/.../task/TaskService.java` | 業務処理を行うService層（キーワードの有無で全件取得と検索を切り替える、タスク作成時に既定値と並び順を決める、列が変わったタスクを移動先の一番下に置くなど。一番下の並び順は、削除で番号に隙間があっても重ならないよう「列の最大値＋1」で決める）。読み取り・作成・更新（PUT／PATCH）・削除・並び替えを担当。`@Transactional` で、メソッドごとのDB操作を「全部成功か、全部取り消し」にする（読み取りは `readOnly`） |
| `src/main/java/.../task/TaskRequest.java` | タスク作成・更新時のリクエストボディの型（text は空欄不可・255文字まで、status／priority は決められた値のみ） |
| `src/main/java/.../task/TaskPatchRequest.java` | 一部だけ更新（PATCH）するときのリクエストボディの型（すべて省略可。送るなら text は空白だけ不可・255文字まで、status／priority は決められた値のみ） |
| `src/main/java/.../task/ReorderRequest.java` | 並び替えAPIのリクエストボディの型（status と orderedIds は必須、status は決められた値のみ） |
| `src/main/resources/application.properties` | 設定ファイル（ポート番号、DB接続情報など） |
| `src/test/java/.../BackendApplicationTests.java` | 起動確認用の基本テスト |

## 実行時の設定値（`application.properties`）

| 項目 | 値 |
| --- | --- |
| アプリ名 | backend |
| ポート番号 | 8080 |
| DB接続先 | `jdbc:postgresql://localhost:5432/taskdb`（Docker の PostgreSQL。Windows に直接インストールした PostgreSQL のサービスは停止しておく） |
| DBユーザー | 環境変数 `DB_USERNAME`。なければ postgres（開発用） |
| DBパスワード | 環境変数 `DB_PASSWORD`。なければ postgres（開発用。本番では環境変数で渡し、ファイルには書かない） |
| open-in-view | false（DBの操作は Service の `@Transactional` の中だけで行う） |

DBのドライバと方言（dialect）は、接続先のURLから自動で決まるので書いていない。

## 静的解析（PMD）

PMD は、Java のコードから「バグになりやすい書き方」を見つける道具。規則は PMD が用意している `quickstart` を使う（`build.gradle` の `pmd { }`）。

| 実行場所 | コマンド | 説明 |
| --- | --- | --- |
| `backend`フォルダ | `./gradlew pmdMain pmdTest` | 本体とテストのコードをチェックする。1件でも見つかると失敗し、場所と規則名が表示される（`./gradlew check` にも含まれる） |

- 見つかったものは、基本は直す。PMD の指摘が Spring の書き方と合わない（的外れな）ときだけ、その場所に `@SuppressWarnings("PMD.規則名")` を付けて止め、止めた理由をコメントに書く（例：[BackendApplication.java](src/main/java/com/taskmanagement/backend/BackendApplication.java) の `UseUtilityClass`）
- 止める範囲はなるべく狭くする（プロジェクト全体で止めると、ほかの場所の本当の問題も見逃すため）
- GitHub Actions（`taskmanagement/.github/workflows/ci.yml`）でも、PR ごとに `./gradlew pmdMain pmdTest compileJava` が自動で動く

## 起動手順（DB + バックエンド）

PostgreSQLはインストール不要で、Dockerコンテナとして起動する（設定ファイルは`taskmanagement/docker-compose.yml`）。

| 順番 | 実行場所 | コマンド | 説明 |
| --- | --- | --- | --- |
| 1 | `taskmanagement`フォルダ | `docker compose up -d` | PostgreSQLをDockerで起動 |
| 2 | `backend`フォルダ | `./gradlew bootRun` | バックエンド（Java）を起動（初回起動時に`tasks`テーブルが自動作成される） |
| 3（任意） | `taskmanagement`フォルダ | `docker compose exec -T postgres psql -U postgres -d taskdb < db/seed-test-data.sql` | テストデータ10件を投入（既存データはすべて消えて入れ直される） |

DBを止めるときは`taskmanagement`フォルダで`docker compose down`を実行する（`docker compose down -v`にするとデータも消えるので注意）。

## 提供しているREST APIエンドポイント

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | /api/tasks | 全タスク取得 |
| GET | /api/tasks?keyword={キーワード} | タスク名にキーワードを含むタスクを検索（部分一致・大文字小文字を区別しない。空なら全件） |
| GET | /api/tasks/{id} | タスクを1件取得（存在しない場合は404） |
| POST | /api/tasks | タスク作成（列の一番下に追加。status 省略時は todo、priority 省略時は medium。成功時は201、入力が不正なら400） |
| PUT | /api/tasks/{id} | タスクを丸ごと更新（status／priority 省略時は今の値のまま。列が変わるときは移動先の一番下に置く。存在しない場合は404、入力が不正なら400） |
| PATCH | /api/tasks/{id} | タスクの一部だけを更新（送った項目だけを書き換える。存在しない場合は404、入力が不正なら400） |
| DELETE | /api/tasks/{id} | タスク削除（成功時は204、存在しない場合は404） |
| PUT | /api/tasks/reorder | 並び替え（指定した列の並び順を、送った ID の順にまとめて振り直す。成功時は204、入力が不正なら400） |
